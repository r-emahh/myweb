# プロジェクト要件定義およびインフラ構成仕様書

## 1. プロジェクト概要

- **プロジェクト名**: myweb (株式会社pop / POP制作所 公式サイト)
- **ステータス**: 初期セットアップ・インフラ構築完了

---

## 2. サイトの目的とターゲット要件

### 2.1 サイトの目的
1. **認知拡大**:
   - 株式会社popの事業内容、クリエイティブ方針、強みを明確に提示し、企業およびブランドの認知向上を図る。
2. **リード・お問い合わせ獲得**:
   - 訪問者（見込み顧客）がスムーズに相談・見積もり依頼・協業提案を行えるよう、明確な導線（CTA）を設計し、新規案件・リードの獲得を促進する。

### 2.2 メインターゲット層
- **見込み顧客（BtoB）**:
  - Webサイトやデジタルクリエイティブの制作・リニューアルを検討している企業担当者、マーケター、事業責任者。
- **ビジネスパートナー**:
  - 協業やパートナーシップを検討しているクリエイティブエージェンシーや開発チーム。

---

## 3. インフラ・ホスティング構成

### 3.1 ホスティング環境
- **プロバイダ**: GitHub Pages
- **ホスティング種別**: 静的サイトホスティング (Static Site Hosting)
- **選定理由**:
  - 静的サイト構成（HTML/CSS/JavaScript）に最適化されており、高可用性・高速配信・ゼロ運用コストを実現できるため。
  - GitHubリポジトリと完全に統合され、Gitベースの安全なCI/CDパイプラインが構築可能なため。

### 3.2 ドメインおよびSSL/TLS
- **公開URL (ドメイン)**: `https://r-emahh.github.io/myweb/`
- **SSL/TLS (HTTPS)**: GitHub Pagesにより自動有効化（Let's Encrypt証明書）。常時HTTPS接続による通信の暗号化と安全性を保証。

### 3.3 デプロイパイプライン (CI/CD)
- **デプロイ方式**: GitHub Actions による自動デプロイ
- **対象ブランチ**: `master`
- **ワークフロー定義**: `.github/workflows/deploy-pages.yml`
- **静的配信設定**: リポジトリルートに `.nojekyll` を配置し、Jekyllによる特殊パス・ファイルのビルド除外を防止。

---

## 4. 運用・開発方針

- **ローカル開発環境**:
  - 起動スクリプト: `pwsh -File scripts/serve.ps1`
  - ローカルURL: `http://127.0.0.1:8080/`
- **ワークフロー管理**:
  - GitHub Issueを起点とし、Issue Flow規約（Planner / Executor / Verifier / Reviewer）に従って安全に開発・更新を行う。
